# 上传归属与生命周期

## 存储与部署约束

1. 图片归属记录由 MySQL 持久保存；图片卷与数据库都需要备份。未登记归属的文件不能仅凭路径删除、认领或绑定到笔记。
2. 如需补录文件，必须核验所有者及全部引用；已引用图片标记为 BOUND。无法核验归属时保持受保护状态。
3. 图片根目录及所有祖先目录必须由可信主体控制；部署账号独占写权限。代码拒绝路径别名、目录删除和符号链接，但不把路径预检查宣称为对恶意本机并发替换目录的完整沙箱。Windows 重解析点与共享盘部署需单独验证。
4. 多实例必须使用一致的共享持久图片存储；仅共享数据库、不共享图片卷不能保证每个实例都能读取文件。

## 新上传状态

- `UPLOADING`：先提交归属预留，再写文件，避免无任何记录的常规写入。
- `READY`：文件写入完成并确认，允许本人发布绑定或删除草稿。
- `BOUND`：已与博客一起在同一数据库事务中提交；上传删除接口不能删除，即使调用者是所有者。
- `DELETING`：删除许可已提交，发布不再允许绑定；文件删除失败或应答丢失可重试。
- `DELETED`：删除应答已完成，保留归属墓碑，重复删除不再次触碰文件。
- `FAILED`：写入阶段失败。部分文件清理失败时仍可能有残留，需要人工核查。

文件系统与 MySQL 不是一个事务。READY 应答不明时不立即删除文件，因为数据库可能已提交成功；保留 UPLOADING/READY 和文件，避免补偿误删。DELETING 应答不明时通过重试继续，而非重新允许绑定。

## 发帖与删除权限

新建笔记最多 9 张、不重复、且必须是本人 READY 图片。发布失败时，博客插入及此前完成的图片绑定一起回滚；所有者和展示计数由服务端设置，不信任请求中的 userId/liked/comments/id。

绑定和删除竞争通过同一图片行锁串行化；多图按规范路径排序锁定。READY 图片若已被博客引用，删除仍拒绝。输入路径统一为严格的 `blogs/0..15/0..15/UUID.ext`，兼容上传响应 `/blogs/...` 与静态资源 `/uploads/blogs/...`。

发布事务在关注动态 Redis 投递前完成；关注动态投递与博客数据库提交仍非原子，需要按真实故障情况评估可靠性。

## 保守的清理流程（未启用自动清理）

仅生成候选，不能将“超过时限”直接等同于可删除。下面 SQL 只读，不执行清理：

```sql
SELECT path,user_id,state,blog_id,create_time,update_time
FROM tb_upload_asset
WHERE state IN ('UPLOADING','FAILED','READY','DELETING')
  AND update_time < DATE_SUB(NOW(), INTERVAL 7 DAY)
ORDER BY update_time,path
LIMIT 100;
```

需逐项核查正在进行的上传、所有博客引用、文件是否存在及备份：

- DELETING：原所有者可重试删除接口；缺失文件也可完成应答。
- READY：不能自动清理用户未发布的草稿；由所有者删除或经明确的保留策略处理。
- UPLOADING/FAILED：仅在确认无活跃请求、无引用且有备份后，由受控运维流程回收。
- BOUND 及未知归属图片：不在清理范围内。

项目未启用默认定时删除任务；文件回收需要人工核查。

## 验证边界

真实临时目录单测验证写入、删除、重试、符号链接拒绝和失败补偿；Windows 无符号链接创建权限时该项明确跳过，由 Linux CI 再验证。

真实 MySQL 集成验证持久归属、发布绑定/回滚、越权拒绝、绑定与删除竞争及删除确认幂等。Redis 故障使用替身，不是线上故障注入。完整栈 smoke 同时覆盖真实 HTTP 上传/读取、越权删除与引用拒绝、发布绑定、已引用图片保护、草稿删除与重试；会话通过 Redis 注入测试夹具，仍不等于浏览器登录 E2E。上传 smoke 需要宿主机 Python 3，GitHub Ubuntu runner 已提供。

真实 HTTP 烟测还覆盖删除后匿名读取返回 404；登录拦截器仅对容器内部到 `/error` 的 ERROR 分派保留原始错误状态，直接访问 `/error` 或业务接口仍受登录校验。
